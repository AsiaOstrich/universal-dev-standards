## Database: Prisma ORM — but the engine is not specified anywhere in this repo

What's actually here:
- `package.json:6` — `@prisma/client` ^6.2.0 as a dependency, `prisma` ^6.2.0 as a devDependency
- `src/server.ts:2-3` — instantiates `PrismaClient` and queries `db.order.findUnique(...)`

That tells you the data access layer is Prisma. It does **not** tell you the underlying database. The engine would be declared in `prisma/schema.prisma` under `datasource db { provider = ... }`, and there is no `prisma/` directory in this repo. There's also no `.env` / `.env.example` with a `DATABASE_URL`, no `docker-compose.yml`, and no CI config. So PostgreSQL, MySQL, SQLite, SQL Server, MongoDB, or CockroachDB are all still on the table — I'd be guessing if I named one.

## Migrations: no migration setup exists in this repo

- No `prisma/migrations/` directory
- No migrate script in `package.json` — the only scripts are `dev` (`tsx src/server.ts`) and `build` (`tsc -p .`)

Prisma's *conventional* commands are `npx prisma migrate dev` locally and `npx prisma migrate deploy` in production, but nothing in this repository confirms that's how this project does it — and without a `schema.prisma`, those commands wouldn't run as-is.
