# 延後項目出口標準

> **Language**: [English](../../../core/deferred-item-exit.md) | 繁體中文

**版本**: 1.0.0
**最後更新**: 2026-08-24
**適用**: 任何標準要求產出、且可能記下延後項目的文件
**範圍**: universal

---

## 目的

有一批標準會要求產出**會產生延後項目**的文件——ADR 的既受風險與「之後再決定」、
規格的未納入清單、retrospective 的 action items、探索矩陣裡未確認的候選、
review 的非阻斷建議、AC 報告的缺口。每一條標準都規定了那份文件要怎麼寫好，
**沒有一條規定那些項目之後去哪**。

於是它們哪裡也沒去。項目被記下、文件被核准，**那筆紀錄就是終點**。
沒有東西會再提起它，因為承載它的只有一份已被視為完成的檔案裡的一段文字。

**本標準補上那個缺失的關係：延後項目必須離開文件。**

---

## 本標準的寫法，以及為什麼這樣寫

**讀下面任何一條要求之前先讀這一段。它拘束它們全部。**

UDS 定義**活動**，採用層負責**編排**（DEC-049；見 [MIGRATION-v6](../../../docs/MIGRATION-v6.md) §2）。
6.0.0 依該決策移除八條機器可讀標準，其中七條正是工作流狀態協定。
**一份寫成編排協定的標準屬於採用層，不屬於這裡。**

本標準受此拘束的分界：

| 這裡容許——**what** | 這裡不容許——**how** |
|---|---|
| artefact 之間必須存在的關係 | artefact 必須通過的狀態機 |
| 一項宣稱要算作證據所必須具備的性質 | 必須產出該宣稱的 pipeline 階段 |
| 一份回報必須保留的區別 | 回報格式、工具或 schema |
| 延後項目必須有出口 | 哪一個 issue tracker／看板／檔案是那個出口 |

**下面每一條要求都寫成「必須存在什麼關係」，絕不寫成「應使用什麼機制維持它」。**
UDS 本來就有一整類這個形狀的標準——[acceptance-criteria-traceability](acceptance-criteria-traceability.md)
要求每一條 AC 都能被某個測試到達，而不規定用什麼維持那條可達性。
本標準是同一個形狀，套用在延後項目上。

**直說它的後果**：本標準**不附帶任何閘門**。它只說什麼必須為真。
有沒有東西在檢查，是採用專案的決定——而 DEX-004 是用來讓那個決定沒辦法被默默做掉的。

## 不變量

**一個記錄在文件裡的延後項目，必須在該文件之外有一個可追蹤的出口，而該出口的識別字必須寫在文件裡、緊鄰該項目。**

### 什麼算延後項目

任何被該文件記錄為**現在不做、不由這份文件做**的項目。措辭變化無窮——
「待決定」「第一版未納入」「另案處理」「尚未實作」「之後再看」「既受風險」「這個我們先放著」。
**措辭不是定義**；定義是該項目相對於「這份文件所了結的那份工作」的狀態。見[錨點](#錨點走訪結構不走訪措辭)。

### 什麼算出口

**刻意不指定。** issue、tracked TODO、manifest 條目、backlog 檔案的一列、
專案已經在跑的任何工單系統——全都算。判準是**「這個項目離開文件了嗎」**，不是「用了什麼工具」。

一個出口要滿足不變量，下列三條必須同時成立：

| # | 關係 | 何時失敗 |
|---|---|---|
| 1 | 出口存在於這份文件之外 | 該項目唯一的紀錄就是這份文件的文字 |
| 2 | 出口可由一個寫在文件裡的識別字定址 | 文件寫著「之後再處理」而沒有任何可定址的東西 |
| 3 | 產出該文件的那次變更落地**之後**，出口仍然解析得到 | 出口被同一次變更關閉、刪除或取代 |

第 3 條不是假想。兩個實際觀察到的洩漏，都同時滿足第 1、2 條而仍然遺失項目：

- 待辦寫進**會被本次合併關閉的 issue**。文件指向一筆在工作被接受的當下就停止存在的紀錄。
- 待辦寫進出口的**留言而非本體**，被後續留言推走。出口解析得到；讀出口卻讀不到那個項目。

## 要求

| ID | 要求 | 嚴重度 |
|---|---|---|
| **DEX-001** | 文件裡記下的延後項目，在文件之外有可追蹤的出口，且文件在該項目旁載明出口識別字 | error |
| **DEX-002** | 產出該文件的變更落地之後，出口仍然解析得到，且仍承載該項目 | error |
| **DEX-003** | 本標準的每一條要求都可表述為 artefact 之間可判定的關係。不能如此表述的要求不得進入本標準 | error |
| **DEX-004** | 被提出作為本標準證據的檢查，已被觀察到對刻意違規的樣本回報失敗。從未紅過的檢查不是可採信的證據 | error |
| **DEX-005** | 驗證確立「那個出口**承載這個項目**」——而不只是「識別字解析得到」 | error |
| **DEX-006** | 「有連結且已驗證內容」與「有連結但內容未驗證」回報為兩個相異狀態。合併為單一通過狀態即不滿足 DEX-005 | error |
| **DEX-007** | 「這裡有一個延後項目」的錨點，是可由該文件自身既定結構窮舉出來的位置 | error |
| **DEX-008** | 以措辭清單補充結構錨點時，明示其涵蓋率未知，且其綠燈不被回報為完整 | warning |
| **DEX-009** | 該判定所用的任何窗口或閾值，載明來歷，或標為未校準 | warning |

## 一條無法被檢查的要求，不是這裡的要求

**DEX-003 是對本標準自身內容的約束。** 上面每一條都指名了 artefact 與它們之間的關係，
使得讀的人——或專案自己建的東西——可以判定它成不成立。
**一條無法被判定的要求不屬於這裡**，不論它聽起來多正確。

理由是量出來的，不是美學：在這一類規則之下第一次大批產出文件，**五項延後項目全部漏掉**。
規則被理解了，人也稱職。缺的是任何一個能分辨「滿足它的文件」與「不滿足它的文件」的東西。

### 一支從未紅過的檢查

**DEX-004 講的是什麼算證據，不是要你去建什麼。**
**一支從未失敗過的檢查，與一支不可能失敗的檢查，輸出一模一樣。**
在它被觀察到「對一個刻意違規的樣本回報失敗」之前，它不是「規則成立」的證據，
只是「有東西跑過」的證據。

證明檢查非空跑的做法、以及為何必須逐子集而非整體進行，見 [class-level-fix](class-level-fix.md)；
「exit 0」為何不等於「它在工作」，見 [verification-evidence](verification-evidence.md)。
**兩者都不在此複述。**

---

## 連結存在，不等於連結有效

一個寫在延後項目旁邊的識別字，製造出「有出口」的外觀。
那個出口**有沒有承載**這個項目，是另一個問題，而兩個答案不能互換。

命名這條規則的實例：文件寫著「與 issue #19 一併決定」，而 #19 裡根本沒有這件事。
上面第 1、2、3 條全部成立，項目照樣不見了。
**一道只問識別字在不在的閘門會放行這份文件**，而它印出的綠燈，
與它印在出口都為真的文件上的綠燈，逐位元相同。

### 兩態，不得合併為一

確立 DEX-005 需要讀出口的內容，成本明顯高於讀文件。
**DEX-005 不要求一步到位做到每一處。** 它要求的是「差別必須看得見」：

| 狀態 | 意義 |
|---|---|
| **有連結且已驗證內容** | 讀過出口，它承載這個項目 |
| **有連結但內容未驗證** | 識別字在；它有沒有承載這個項目，未知 |
| **無出口** | 違反 DEX-001 |

把前兩態合併成單一通過數，不是通往規則的捷徑——那正是這條規則要防的缺陷，
被制度化並給了一個編號。**一個被回報成通過的未知，比一個被回報成未知的未知更糟**，
因為後者還找得到。

若一個專案今天只做得起便宜的那一半，那屬於 [verification-evidence](verification-evidence.md) VE-012
與 [class-level-fix](class-level-fix.md) CLF-008 已經在管的涵蓋缺口：
**必須帶日期登記，不能只在文字裡揭露一次。** 此處不複述。

## 錨點：走訪結構，不走訪措辭

判定「這裡有沒有延後項目」時，**走訪文件的結構**。
結構由「要求產出這份文件的那條標準」所定義，因此可窮舉。
**措辭不可窮舉，而且沒有任何一張措辭清單能被證明是完整的。**

| 文件 | 延後項目出現的結構位置 |
|---|---|
| ADR | `Consequences` → **Bad**／**Accepted risk**；`Links`；被考慮而未採用的選項 |
| 規格 | 未納入／不在本版的段落；open questions；待確認的 assumptions |
| Retrospective | `Action Items`；`Previous Action Items Review` 中仍為 Open 的列；附理由 Cancelled 的項目 |
| 功能探索 | 零打勾候選；`dead_code_candidates`；升級為人工觀察的候選 |
| Code review | 本次未改而被接受的非阻斷留言類別（`⚠️ IMPORTANT`、`💡 SUGGESTION`、`[SUGGESTION]`、`[NIT]`）|
| AC 覆蓋率報告 | `Gaps` → **Uncovered AC**／**Partial AC**；`Threshold Exceptions`；`Action Items` |

### 仍然要用措辭清單時

合法——結構走訪抓得到待在自己段落裡的項目，抓不到被丟進一段敘述文字裡的那一個。
但此時 **DEX-008 隨即適用**：該清單的涵蓋率未知，這件事必須明說，
而它的綠燈不得被讀成「沒有漏掉任何延後項目」。
一張含「待決定」與「未納入」的清單，對「這一點我們先放著」這句話**什麼也沒說**。

**一道自行列舉範圍的閘門，正確到有人新增第四個成員為止**——
[class-level-fix](class-level-fix.md) 是這個失敗的通則形式。
措辭清單在構造上就是那個失敗；它可以用，但不能信。

### 閾值必須帶著來歷

**DEX-009。** 「識別字必須出現在項目後 3 行內」這類判準，決定了建立其上的一切的召回率。
若沒有東西記下 3 是怎麼來的，就沒有人能評估把它改成 2 或 5，
也沒有人分得出它是量出來的還是猜的。
**寫下那個數字的來歷，或標為未校準。** 兩者都可接受；沉默不行。

**一個沒有來歷的閾值，是一個沒有人能檢查的決定。**

## 反模式

| 反模式 | 為什麼失敗 |
|---|---|
| 記下延後項目，然後核准文件 | 文件是唯一的載體，而它現在被視為完成了 |
| 出口被產出該文件的同一次變更關閉 | 指標在工作進行中解析得到，工作結束後就不再解析得到 |
| 項目寫進出口的留言，不是出口本體 | 出口解析得到；讀出口卻讀不到那個項目 |
| 檢查識別字在不在 | 「在」與「對」印出同一個綠 |
| 已驗證與未驗證的連結共用一個通過狀態 | 把上一列的缺陷變成永久的，還給了它一個編號 |
| 把措辭清單當成「延後」的定義 | 正確到有人換一種寫法為止，而沒有東西會說 |
| 沒有記下來歷的窗口大小 | 它決定整個判定的召回率，而沒有人能檢查它 |
| 從未被觀察到失敗的檢查 | 與一支不可能失敗的檢查無從分辨 |

## 什麼在執行本標準

**UDS 側沒有任何東西在執行，而這件事是被記錄的，不是被暗示的。**
UDS 陳述關係；有沒有東西去判定它，依上面的[寫法約束](#本標準的寫法以及為什麼這樣寫)，是採用專案的決定。

本標準做的事，是讓那個決定顯形：DEX-003 保證這裡每一條**能**被判定，
DEX-004 固定「一次判定要算數需要什麼」，DEX-006／DEX-008 固定「一次不完整的判定容許印出什麼」。
一個採用本標準而什麼都沒建的專案**並未違反它**——
但它同樣不能宣稱自己的延後項目有出口，因為它沒有任何可採信的證據說明有。

**重啟條件**：若 UDS 開始出貨那些文件本身，而不只是出貨要求產出它們的標準，
走訪[錨點](#錨點走訪結構不走訪措辭)那張表所列的結構位置就在本 repo 內變得可能，
屆時誠實的做法是去跑它。

## 會產出延後項目的標準

下列各條都指回這裡；**沒有一條複述規則**，因為同一條規則的六份副本會往六個方向腐壞。

- [adr-standards](adr-standards.md) — 既受風險、負面後果、被考慮而未採用的選項
- [spec-driven-development](spec-driven-development.md) — 未納入項目、open questions、待確認的 assumptions
- [retrospective-standards](retrospective-standards.md) — action items，以及仍為 Open 的上期項目
- `feature-discovery-standards` — 未確認候選與 `dead_code_candidates`
- [code-review-checklist](code-review-checklist.md) — 本次未改而被接受的非阻斷留言
- [acceptance-criteria-traceability](acceptance-criteria-traceability.md) — 涵蓋缺口、閾值例外、報告的 action items

## 與其他標準的關係

- [acceptance-criteria-traceability](acceptance-criteria-traceability.md) — 上一層的同一個形狀：
  它要求每條 AC 都能被驗證項到達，而不規定用什麼維持。本標準要求每個延後項目都能被出口到達。
- [class-level-fix](class-level-fix.md) — 提供 DEX-004 所要求證據的產生程序；
  也是 DEX-008 所揭露之措辭清單失敗的通則形式。
- [verification-evidence](verification-evidence.md) — VE-012 的帶到期日例外清冊，
  正是 DEX-006 那群「未驗證」項目該被登記進去的地方，而不是揭露一次就放著。
- [self-review-protocol](self-review-protocol.md) — 自我複查抓得到矛盾、抓不到缺漏；
  沒有出口的延後項目正是缺漏。
