# 回合收尾完整性

> **Language**: [English](../../../core/turn-completion-integrity.md) | 繁體中文

**版本**: 1.2.0
**最後更新**: 2026-09-08
**適用範圍**: 任何由 agent 結束回合、把控制權交還給人的執行環境
**Scope**: universal
**產業標準**: 不宣稱任何來源——由實際觀察到的失敗歸納，見「證據」

---

## 目的

agent 寫下「我接著做 X」，然後結束回合，而 X 沒有做。

人讀到的是一句描述著從未發生的工作的話。沒有任何錯誤、沒有任何檢查變紅，
逐字稿讀起來像有進展。下一個回合從一個「人以為比實際更前面」的狀態開始。

這不是知識上的失敗——agent 說對了下一步。這是**收尾**的失敗：
回合結束在工作本該開始的那一刻。

---

## 規則

**R1.** 若 agent 最後一則訊息做出了第一人稱的下一步宣告，
回合**不得**結束，除非那件事做了，或說出它卡在什麼。

**R2.** 「卡在什麼」的意思是逐項指名每一件事在等誰、等什麼。
「主要的都做完了」不是卡點陳述；
「部署等你的金鑰，文件不卡任何人而我現在就做」才是。

**R3.** 只寫在 agent 指令裡的規則不是執法。R1 必須**在回合結束的那一刻**、
由**不是 agent 的東西**來判斷。

---

## R3 為什麼存在

這條規則的指令形式曾寫進某專案的 agent 指令，
而**在讀到它的同一個 session 內就被違反**。
接著它被寫成已發布的標準、標為 optional、沒有任何檢查器在讀，
七天後同樣的違反再來一次。

指令是一種輸入。失敗發生在一個決策點——「我正要結束這個回合」——
而一個在那一刻不會被讀到的輸入，就是沒有在生效。
一般形式是：**一項有文件而在其決策點上沒有執法的要求，是建議；
它的遵循度不是很高，是沒有被量過。**

---

## 這個檢查**不得**做的事

**R4. 不得因為「永遠還有待辦」而擋。** repo 永遠有未關的 TODO，
待辦清單永遠有項目。一道每個回合都為真的閘門會被關掉，然後它什麼都不保護。
這個檢查**只**在 agent 於那則訊息裡做出的宣告上觸發。

**R5. 一律 fail open。** 任何錯誤——讀不到逐字稿、欄位缺、JSON 壞掉、
結構不符——都**必須**讓回合結束。一支會把 session 困住的 hook 比沒有 hook 糟，
因為人唯一的救援手段是把它關掉，而他會永久關掉它。

**R6. 阻擋要有上界。** 檢查**必須**同時具備
(a) 兩次阻擋之間的冷卻期，與
(b) **滾動時窗**內的阻擋次數上限。

以 session 計且永不重置的上限不是安全閥——它是一個有延遲的關閉開關，
而且會在「這條規則最重要的那種長 session」裡安靜地自我解除。

---

## 使用者可以結束回合，而 agent 的用字說不出這件事

**R9.** 檢查**必須**豁免由人要求結束的回合，
而且**必須**從人自己最近一則訊息判斷，不是從 agent 的訊息判斷。

這條規則的存在是因為它的缺席被量到過一次——就在本標準上線後的第一次真實觸發。
人寫的是「先暫停，我要回家了」；agent 照做並列出回來要接的事；
檢查把它讀成未兌現的承諾並擋下。

偵測器對樣式的判斷沒有錯。**由指令結束的回合，與由未兌現承諾結束的回合，
在 agent 的用字上一模一樣**，因為兩種情況下 agent 都在指名自己現在不做的工作。
那則訊息裡沒有任何東西分得出來，所以只讀那則訊息的檢查也分不出來。

**R10.** 叫停樣式**必須**寫窄，而且它的語料**必須**包含
「只是含有停止字眼的工作指令」。誤豁免不是漏擋一次，
而是把檢查在該 session 的剩餘時間全部靜音。
實作期間該樣式曾比對到「先停用那份硬編碼清單，改成走訪註冊表」
——一句要求做事的指令，被讀成叫停。

**R11.** 檢查自己的攔阻訊息會以人的回合回到逐字稿。
它**必須**認得出自己的輸出，並在尋找人的最後一則訊息時略過它。

沒有這一條，R9 只會生效一次。攔阻訊息會在下一次執行成為「人最近一則訊息」，
真正那句叫停被蓋在它後面，豁免就消失——而且是靜默地、
只在它被建立的那種情境裡消失。

這與「偵測器比對到解釋它的散文」同一族，再往前一步：**檢查讀到自己的輸出。**
在攔阻訊息裡帶一個固定標記字串，略過任何含有它的人類回合。

---

## 語言涵蓋是正確性問題，不是翻譯工作

這個檢查讀的是 agent 寫的散文，所以**它的偵測器與語言綁定**。
一個只帶著某一種語言樣式的偵測器，出貨給以另一種語言工作的採用者，
會得到一支裝好了、每回合都執行、exit 0、而**結構上永遠不會觸發**的 hook。
每一個可觀察的訊號，都與「agent 表現良好」一模一樣。

**R7.** 每一個支援的語言**必須**以 locale 包出貨，
各自帶著**自己的語料**（必須擋的案例與必須放行的案例），
而該包的自測**必須**在 CI 裡跑。語料不過的 locale 包不出貨。

**R8.** 語言沒有對應包的採用者**必須**被告知這個檢查對他們是失效的。
在這裡沉默，等於把本標準要防的失敗在上一層重演一次。

---

## 偵測器比對什麼

形狀是：**第一人稱未來標記，接一個動作動詞，在同一個句子裡**，再減掉三個排除項。

| 元素 | 作用 | 缺了會怎樣 |
|---|---|---|
| 第一人稱＋未來標記 | 把宣告與描述分開 | 會比對到被引述回來的使用者原話 |
| 動作動詞 | 把「做」與「講」分開 | 「我來解釋為什麼」會算成工作 |
| 限定同一句 | 讓兩半保持相關 | 一個否定子句與後面一個真承諾會併成一個不匹配 |
| 排除報告動詞 | 「我會說／提／記」不是工作 | 檢查會在自己的摘要上觸發 |
| 排除否定 | 「我不會改那個」是決定，不是承諾 | 一句拒絕會被讀成承諾 |
| 排除引用與表格 | 樣式的**例子**不是樣式的**實例** | 檢查會在自己的文件上觸發 |

上表每一個排除項，都是因為它的缺席在測試中造成過一次誤擋才加上去的。
少做其中任何一項的實作，會重現那次誤擋。

---

## 證據

單一專案的觀察，2026-08 至 2026-09：

| 觀察 | 次數 |
|---|---|
| 使用者就「說了下一步卻沒做」提出同一個抱怨 | 5 |
| 指令形式已存在、而在同一個 session 內被違反 | ≥1 |
| 偵測器版本被自己原始碼或例子中的樣式打敗 | 5 |
| 上線前被語料抓到的偵測器誤擋 | 3 |

最後一列就是 R7 的論據。五個偵測器缺陷裡有三個**只因為語料存在**才被抓到；
出貨出去的那兩個，正是沒有任何案例涵蓋的那兩個。

---

## 檢查清單

- [ ] 檢查在回合結束時執行，不是寫成給 agent 的指令
- [ ] 每一條失敗路徑都不阻擋、直接放行
- [ ] 冷卻期與滾動時窗上限兩者都在
- [ ] 每個出貨語言都有語料，而語料在 CI 裡跑
- [ ] 語言不支援的採用者被告知檢查失效
- [ ] 檢查不讀取 repo 狀態（未關的 TODO、待辦清單）
- [ ] 由人要求結束的回合被豁免，且由人的訊息判斷
- [ ] 叫停語料包含「含有停止字眼的工作指令」
- [ ] 檢查認得出自己的攔阻訊息，不把它讀成人說的話
