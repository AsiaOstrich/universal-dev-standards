# 估算標準

> **語言**: [English](../../../core/estimation-standards.md) | 繁體中文

**版本**: 1.0.0
**最後更新**: 2026-04-01
**適用範圍**: 所有軟體專案
**範疇**: universal
**產業標準**: Agile Estimation, PERT, Wideband Delphi
**參考資料**: [Mountain Goat Software](https://www.mountaingoatsoftware.com/), [Steve McConnell - Software Estimation](https://www.construx.com/)

---

## 概述

本文件定義軟體開發專案的估算標準。內容涵蓋估算方法、校準機制、常見反模式、信心等級、重新估算觸發條件，以及估算與承諾之間的關鍵差異。

良好的估算不在於精準無誤——而是在於對不確定性保持透明，並透過校準隨時間持續改進。

## 估算方法

### 1. Planning Poker

一種基於共識的估算技術，團隊成員使用標有數字的卡片各自獨立估算，接著進行討論並收斂共識。

| 面向 | 詳細內容 |
|------|----------|
| **何時使用** | Sprint 規劃、Story 層級估算 |
| **團隊規模** | 3–9 人 |
| **尺度** | Fibonacci（1, 2, 3, 5, 8, 13, 21）或其修改版 |
| **優點** | 促進討論、減少錨定效應、建立共同理解 |
| **缺點** | 面對大量待辦項目時較耗時、需要同地協作或專用工具 |

### 2. T-Shirt Sizing

一種使用抽象尺寸標籤（XS, S, M, L, XL）進行快速、高層級估算的相對大小評估技術。

| 面向 | 詳細內容 |
|------|----------|
| **何時使用** | 路線圖（Roadmap）規劃、Epic 層級估算、初始待辦清單整理 |
| **團隊規模** | 不限 |
| **尺度** | XS, S, M, L, XL（可選 XXL） |
| **優點** | 快速、認知負擔低、適合處理大量項目 |
| **缺點** | 精確度較低、較難彙整進以時間為基準的計畫中 |

### 3. 三點估算

一種統計技術，使用樂觀（O）、最可能（M）和悲觀（P）估算值來計算預期工期與標準差。

| 面向 | 詳細內容 |
|------|----------|
| **何時使用** | 關鍵路徑項目、高不確定性任務、專案層級規劃 |
| **公式** | E = (O + 4M + P) / 6; SD = (P - O) / 6 |
| **優點** | 量化不確定性、產出信心區間、具備統計學理論基礎 |
| **缺點** | 每個項目需要三個估算值、對小型任務可能感覺過於緩慢 |

## 校準

### 校準機制

團隊應定期對照實際成果校準其估算，以隨時間提升準確度。

**檢視頻率**：在每次 Sprint 回顧會議（Retrospective）進行校準檢視，或至少每個迭代一次。

**估算準確率比率**：

```
Estimation Accuracy Ratio = Actual Effort / Estimated Effort
```

- 比率 = 1.0：完美估算
- 比率 > 1.0：低估（實際耗費時間更長）
- 比率 < 1.0：高估（實際耗費時間較短）

**改進行動流程**：

1. 收集已完成工作項目的實際工作量 vs. 估算工作量數據
2. 計算每個項目與團隊平均的估算準確率比率
3. 找出系統性模式（例如：持續低估整合任務）
4. 定義修正行動（例如：為整合增加緩衝、拆解大型項目）
5. 追蹤後續迭代中的改進成效

## 反模式

下列反模式經常會損害估算品質。每項均列出識別徵兆與緩解策略。

### 1. 錨定偏誤

**說明**：第一個被提及的數字主導了後續的估算，將團隊拉向該錨點。

**識別方式**：估算值聚集在第一個被分享的數值周圍；反對意見未被充分探討。

**緩解策略**：採用盲估（例如：Planning Poker 卡片同時亮出）。避免在獨立評估前公開發表估算值。輪流更換誰先發言。

### 2. 規劃謬誤

**說明**：系統性地低估時間、成本與風險，同時高估效益的傾向。

**識別方式**：專案持續超出估算；事後檢討反覆提及「未預見的複雜度」。

**緩解策略**：使用參考類別預測（Reference Class Forecasting，與過往類似專案進行比較）。套用歷史校準數據。增加明確的風險緩衝。

### 3. 範圍蔓延盲區

**說明**：在估算過程中未能識別或計入逐漸擴大的範疇。

**識別方式**：隨著需求增長，原始估算失去效用；儘管出現顯著的範疇變更，卻未觸發重新估算。

**緩解策略**：估算前先鎖定範疇定義。明確追蹤範疇變更。當範疇變更超過門檻時觸發重新估算（參見重新估算觸發條件）。

### 4. 學生症候群

**說明**：將工作拖延至最後一刻才開始，消耗掉所有可用的緩衝時間。

**識別方式**：儘管時間充裕，工作卻總是延遲開工；所有交付皆由截稿期限的壓力驅動。

**緩解策略**：設定具備可見進度追蹤的中間里程碑。縮短迭代週期。避免在個別估算中灌水——改為使用專案層級的緩衝。

### 5. 帕金森定律

**說明**：工作會自動膨脹以填滿所有可用於完成它的時間，無論實際複雜度為何。

**識別方式**：任務耗時總是與估算時間完全相符，不受難易度變化的影響。

**緩解策略**：使用相對估算（Story Points）而非絕對時間。挑戰剛好落在整數的估算值。追蹤速度（Velocity）趨勢以發現異常。

## 信心等級

每個估算皆應包含標明預期變異範圍的信心等級。

| 等級 | 變異範圍 | 說明 | 適用情境 |
|------|----------|------|----------|
| **高** | **±20%** | 理解透徹的工作，具有明確需求與過往經驗 | 重複性任務、定義明確的 Story、熟悉的技術 |
| **中** | **±50%** | 部分理解的工作，帶有一些未知數 | 已知領域中的新功能、中等程度的技術不確定性 |
| **低** | **±100%** | 高度不確定的工作，具有顯著的未知數 | 新技術、不明確的需求、研究探索（Spike） |

### 溝通指引

- **高信心**：「我們估算為 5 天（範圍 4–6 天）」
- **中等信心**：「我們估算為 5 天（範圍 2.5–7.5 天）」
- **低信心**：「我們估算為 5 天（範圍 0–10 天）——建議先進行 Spike 探索」

務必在提出單點估算的同時說明信心等級。絕不要在未明確聲明不確定性的情況下提出低信心的估算。

## 重新估算觸發條件

當出現以下任一情況時，應觸發重新估算：

### 觸發條件

| 觸發條件 | 說明 | 行動 |
|---------|------|------|
| **需求變更** | 新增、移除或修改功能性或非功能性需求 | 重新估算受影響項目；更新信心等級 |
| **技術發現** | 發現新的技術限制、相依性或複雜度 | 依據更新後的知識重新估算；記錄該技術發現 |
| **外部相依變更** | 第三方 API、函式庫或服務的可用性或行為發生變更 | 重新估算整合工作；評估對時程的影響 |
| **超過時間門檻** | 經過時間已超過原始估算的顯著比例（例如 >50%）卻未取得等比例的進展 | 進行檢查點審查；重新估算剩餘工作 |

### 重新估算流程

1. **識別**：確認已符合觸發條件
2. **評估**：評估對現有估算的影響
3. **重新估算**：對受影響項目套用適當的估算方法
4. **溝通**：向利害關係人通知修訂後的估算與更新後的信心等級
5. **記錄**：記錄重新估算的原因以及與原始估算之間的差異（Delta）

## 估算 vs 承諾

### 定義

**估算（Estimate）**是對工作需要耗費多久時間的預測，本質上具有不確定性並以區間表示。這是由實際執行工作的人員所做出的技術評估。

**承諾（Commitment）**是在特定日期前或特定預算內交付成果的保證。這是一項綜合考量估算、風險承受度與策略優先順序的商業決策。

### 估算 vs 承諾 — 關鍵差異

| 面向 | 估算 | 承諾 |
|------|------|------|
| **本質** | 帶有不確定性的預測 | 帶有當責責任的承諾 |
| **負責人** | 開發團隊 | 管理層 / Product Owner |
| **格式** | 帶有信心等級的範圍 | 具體日期或範疇 |
| **變更** | 隨資訊改變而更新 | 與利害關係人重新協商 |

### 溝通實務

- **估算**：始終以帶有信心等級的範圍呈現。使用如「我們估算」或「我們的評估是」等語言。
- **承諾**：以具體目標呈現。使用如「我們承諾」或「我們將於...之前交付」等語言。
- **切勿混淆**：絕不允許在未經明確協商的情況下，將估算默許轉換為承諾。

### 將估算轉換為承諾

1. 從團隊的估算開始（範圍 + 信心等級）
2. 評估組織的風險承受度（若未能如期達成會發生什麼事？）
3. 根據信心等級加入適當的緩衝
4. 與利害關係人協商範疇、時程或品質的取捨
5. 將承諾與作為基礎的估算分開記錄
