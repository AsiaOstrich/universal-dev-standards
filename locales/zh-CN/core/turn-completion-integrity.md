# 回合收尾完整性

> **语言**: [English](../../../core/turn-completion-integrity.md) | [繁體中文](../../zh-TW/core/turn-completion-integrity.md) | 简体中文

**版本**: 1.2.0
**最后更新**: 2026-09-08
**适用范围**: 任何由 agent 结束回合、把控制权交还给人的执行环境
**Scope**: universal
**行业标准**: 不声称任何来源——由实际观察到的失败归纳，见「证据」

---

## 目的

agent 写下「我接着做 X」，然后结束回合，而 X 没有做。

人读到的是一句描述着从未发生的工作的话。没有任何错误、没有任何检查变红，
对话记录读起来像有进展。下一个回合从一个「人以为比实际更靠前」的状态开始。

这不是知识上的失败——agent 说对了下一步。这是**收尾**的失败：
回合结束在工作本该开始的那一刻。

---

## 规则

**R1.** 若 agent 最后一条消息做出了第一人称的下一步声明，
回合**不得**结束，除非那件事做了，或说出它卡在什么。

**R2.** 「卡在什么」的意思是逐项指名每一件事在等谁、等什么。
「主要的都做完了」不是阻塞点陈述；
「部署等你的密钥，文档不卡任何人而我现在就做」才是。

**R3.** 只写在 agent 指令里的规则不是执法。R1 必须**在回合结束的那一刻**、
由**不是 agent 的东西**来判断。

---

## R3 为什么存在

这条规则的指令形式曾写进某项目的 agent 指令，
而**在读到它的同一个 session 内就被违反**。
接着它被写成已发布的标准、标为 optional、没有任何检查器在读，
七天后同样的违反再来一次。

指令是一种输入。失败发生在一个决策点——「我正要结束这个回合」——
而一个在那一刻不会被读到的输入，就是没有在生效。
一般形式是：**一项有文档而在其决策点上没有执法的要求，是建议；
它的遵循度不是很高，是没有被量过。**

---

## 这个检查**不得**做的事

**R4. 不得因为「永远还有待办」而拦截。** 仓库永远有未关闭的 TODO，
待办清单永远有条目。一道每个回合都为真的闸门会被关掉，然后它什么都不保护。
这个检查**只**在 agent 于那条消息里做出的声明上触发。

**R5. 一律 fail open。** 任何错误——读不到对话记录、字段缺失、JSON 损坏、
结构不符——都**必须**让回合结束。一个会把 session 困住的 hook 比没有 hook 更糟，
因为人唯一的补救手段是把它关掉，而他会永久关掉它。

**R6. 拦截要有上界。** 检查**必须**同时具备
(a) 两次拦截之间的冷却期，与
(b) **滚动时间窗**内的拦截次数上限。

以 session 计且永不重置的上限不是安全阀——它是一个有延迟的关闭开关，
而且会在「这条规则最重要的那种长 session」里悄无声息地自我解除。

---

## 使用者可以结束回合，而 agent 的用词说不出这件事

**R9.** 检查**必须**豁免由人要求结束的回合，
而且**必须**从人自己最近一条消息判断，不是从 agent 的消息判断。

这条规则的存在是因为它的缺席被量到过一次——就在本标准上线后的第一次真实触发。
人写的是「先暂停，我要回家了」；agent 照做并列出回来要接的事；
检查把它读成未兑现的承诺并拦下。

检测器对模式的判断没有错。**由指令结束的回合，与由未兑现承诺结束的回合，
在 agent 的用词上一模一样**，因为两种情况下 agent 都在指名自己现在不做的工作。
那条消息里没有任何东西分得出来，所以只读那条消息的检查也分不出来。

**R10.** 叫停模式**必须**写窄，而且它的语料**必须**包含
「只是含有停止字眼的工作指令」。误豁免不是漏拦一次，
而是把检查在该 session 的剩余时间全部静音。
实现期间该模式曾匹配到「先停用那份硬编码清单，改成遍历注册表」
——一句要求做事的指令，被读成叫停。

**R11.** 检查自己的拦截消息会以人的回合回到对话记录。
它**必须**认得出自己的输出，并在寻找人的最后一条消息时跳过它。

没有这一条，R9 只会生效一次。拦截消息会在下一次执行成为「人最近一条消息」，
真正那句叫停被盖在它后面，豁免就消失——而且是悄无声息地、
只在它被建立的那种情境里消失。

这与「检测器匹配到解释它的散文」同一族，再往前一步：**检查读到自己的输出。**
在拦截消息里带一个固定标记字符串，跳过任何含有它的人类回合。

---

## 语言覆盖是正确性问题，不是翻译工作

这个检查读的是 agent 写的散文，所以**它的检测器与语言绑定**。
一个只带着某一种语言模式的检测器，交付给以另一种语言工作的采用者，
会得到一个装好了、每回合都执行、exit 0、而**结构上永远不会触发**的 hook。
每一个可观察的信号，都与「agent 表现良好」一模一样。

**R7.** 每一个支持的语言**必须**以 locale 包交付，
各自带着**自己的语料**（必须拦截的用例与必须放行的用例），
而该包的自测**必须**在 CI 里运行。语料不通过的 locale 包不交付。

**R8.** 语言没有对应包的采用者**必须**被告知这个检查对他们是失效的。
在这里沉默，等于把本标准要防的失败在上一层重演一次。

---

## 检测器匹配什么

形状是：**第一人称将来标记，接一个动作动词，在同一个句子里**，再减掉三个排除项。

| 元素 | 作用 | 缺了会怎样 |
|---|---|---|
| 第一人称＋将来标记 | 把声明与描述分开 | 会匹配到被引述回来的用户原话 |
| 动作动词 | 把「做」与「讲」分开 | 「我来解释为什么」会算成工作 |
| 限定同一句 | 让两半保持相关 | 一个否定从句与后面一个真承诺会并成一个不匹配 |
| 排除报告动词 | 「我会说／提／记」不是工作 | 检查会在自己的摘要上触发 |
| 排除否定 | 「我不会改那个」是决定，不是承诺 | 一句拒绝会被读成承诺 |
| 排除引用与表格 | 模式的**例子**不是模式的**实例** | 检查会在自己的文档上触发 |

上表每一个排除项，都是因为它的缺席在测试中造成过一次误拦才加上去的。
少做其中任何一项的实现，会重现那次误拦。

---

## 证据

单一项目的观察，2026-08 至 2026-09：

| 观察 | 次数 |
|---|---|
| 用户就「说了下一步却没做」提出同一个抱怨 | 5 |
| 指令形式已存在、而在同一个 session 内被违反 | ≥1 |
| 检测器版本被自己源码或例子中的模式击败 | 5 |
| 上线前被语料抓到的检测器误拦 | 3 |

最后一行就是 R7 的论据。五个检测器缺陷里有三个**只因为语料存在**才被抓到；
交付出去的那两个，正是没有任何用例覆盖的那两个。

---

## 检查清单

- [ ] 检查在回合结束时执行，不是写成给 agent 的指令
- [ ] 每一条失败路径都不拦截、直接放行
- [ ] 冷却期与滚动时间窗上限两者都在
- [ ] 每个交付语言都有语料，而语料在 CI 里运行
- [ ] 语言不支持的采用者被告知检查失效
- [ ] 检查不读取仓库状态（未关闭的 TODO、待办清单）
- [ ] 由人要求结束的回合被豁免，且由人的消息判断
- [ ] 叫停语料包含「含有停止字眼的工作指令」
- [ ] 检查认得出自己的拦截消息，不把它读成人说的话
