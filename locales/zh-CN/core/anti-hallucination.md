# AI 协作防幻觉标准

> **语言**: [English](../../../core/anti-hallucination.md) | [繁體中文](../../zh-TW/core/anti-hallucination.md) | 简体中文

**版本**: 1.5.1
**最后更新**: 2026-04-13
**适用范围**: 所有使用 AI 助手的软件项目
**范围**: universal
**行业标准**: 无（UDS 原创）

> **有关详细示例和案例研究，请参阅[防幻觉指南](../../../core/guides/anti-hallucination-guide.md)**

---

## 目的

本标准为 AI 助手定义了严格的准则，以防止在分析代码、提出建议或记录系统文档时产生幻觉（生成虚假或未经验证的信息）。

---

## 核心原则

### 1. 仅基于证据的分析

| 应做 | 禁止 |
|----|--------|
| ✅ 分析已读取的代码文件 | ❌ 推测未见过的 API、函数或配置 |
| ✅ 引用已获取的文档 | ❌ 在未经核实的情况下假设框架行为 |
| ✅ 引用已检查的配置文件 | ❌ 捏造需求细节 |

### 2. 明确来源标注

**代码引用格式**:
```
[Source: Code] file_path:line_number - Description
```

**外部文档格式**:
```
[Source: External] URL - Description (Version: x.x.x, Accessed: YYYY-MM-DD)
```

**AI 知识格式**:
```
[Source: Knowledge] Topic - Description (⚠️ Requires verification)
```

### 3. 来源类型可靠度

| 来源类型 | 标签 | 可靠度 |
|-------------|-----|-------------|
| 项目代码 | `[Source: Code]` | ⭐⭐⭐⭐⭐ 最高 |
| 项目文档 | `[Source: Docs]` | ⭐⭐⭐⭐ 高 |
| 外部文档 | `[Source: External]` | ⭐⭐⭐⭐ 高 |
| 网络搜索 | `[Source: Search]` | ⭐⭐⭐ 中 |
| 用户提供 | `[Source: User]` | ⭐⭐⭐ 中 |
| AI 知识 | `[Source: Knowledge]` | ⭐⭐ 低 |

---

## 确定性分类标签

| 标签 | 使用时机 |
|-----|----------|
| `[Confirmed]` | 来自代码/文档的直接证据 |
| `[Inferred]` | 基于现有证据的逻辑推论 |
| `[Assumption]` | 基于常见模式（需验证） |
| `[Unknown]` | 信息不可得 |
| `[Need Confirmation]` | 需要用户澄清 |

---

## 推导标签（用于生成内容）

| 标签 | 用途 | 示例场景 |
|-----|---------|-----------------|
| `[Source]` | 直接来自规格/需求的内容 | SPEC 标题、AC 逐字文本 |
| `[Derived]` | 从源内容转换而来 | 从条列式 AC 转换的 GWT |
| `[Generated]` | AI 生成的结构 | 测试骨架、TODO 注释 |
| `[TODO]` | 需要人工实现 | 步骤定义、断言 |

---

## 禁止行为

| # | 禁止行为 | 替代做法 |
|---|-------------|---------|
| 1 | **捏造 API 或函数签名** | 读取实际源代码或询问用户 |
| 2 | **假设需求** | 当需求模糊时提出澄清问题 |
| 3 | **推测未读取的代码** | 声明“需要读取 [文件] 以确认” |
| 4 | **编造配置** | 审查实际配置文件 |
| 5 | **凭空捏造错误或 Bug** | 分析实际代码并引用具体行号 |
| 6 | **提出选项但不推荐** | 始终包含推荐选项并说明理由 |
| 7 | **未分析副作用即实现** | 在实现前列出至少 3 个潜在副作用 |

---

## 推荐要求

**规则**: 当提供多个选项时，始终包含推荐选项并说明理由。

| 场景 | 要求 |
|----------|-------------|
| 提供 2 个以上选项 | 必须标明推荐选项并说明理由 |
| 优劣明显 | 直接推荐最佳选项并说明理由 |
| 存在权衡取舍 | 基于当前上下文推荐，并说明权衡考量 |
| 无法判断 | 说明需要哪些信息才能给出推荐 |

---

## 下一步建议

**规则**: 完成一项任务或子任务后，建议合理的后续步骤并指出最推荐的选项。

**指引**:
- **主动性**: 不要等待用户询问“接下来做什么？”
- **符合上下文**: 建议应遵循项目的工作流程
- **明确推荐**: 使用 `[Recommended]` 标出最佳路径

---

## 实施检查清单

在对代码、需求或架构做出任何陈述之前：

- [ ] **来源已验证**: 我是否已读取实际的文件/文档？
- [ ] **来源类型已标注**: 我是否已指明来源类型？
- [ ] **引用已注明**: 我是否包含了文件路径和行号（针对代码）？
- [ ] **版本已指明**: 在适用情况下，我是否包含了库/框架的版本？
- [ ] **确定性已分类**: 我是否已标注为 [Confirmed]、[Inferred] 等？
- [ ] **AI 知识已标记**: 我是否对 `[Source: Knowledge]` 加上了 ⚠️ 警告？
- [ ] **绝无捏造**: 我是否避免了编造 API、配置或需求？
- [ ] **用户澄清**: 我是否对模糊不清之处请求了澄清？
- [ ] **包含推荐**: 在提供选项时，我是否包含了推荐选项？
- [ ] **已识别副作用**: 我是否在实现前列出了潜在副作用？

## 版本敏感性

**规则**: 引用库、框架或 API 时，只要可用，始终包含版本信息。

| ✅ 良好 | ❌ 不良 |
|---------|--------|
| `[Source: External] Next.js App Router (v14.x) - Server Components are the default` | "Next.js uses Server Components" |
| `[Source: Code] package.json:12 - Using "express": "^4.18.2"` | "Express handles routing" |

## Agent 认识论校准（v1.4.0，XSPEC-008）

Agent 必须使用 Answer/Ask/Abstain 框架声明其认识论状态：

| 动作 | 使用时机 | 必填字段 |
|--------|-------------|----------------|
| `answer` | 拥有足够信息 | 无（completeness/confidence 为选填） |
| `ask` | 缺少关键信息 | `missing_variables` 列表 |
| `abstain` | 确实超出能力范围 | `abstain_reason` |

**Fail-closed Agent**（必须始终回答）：`evaluator`、`guardian`

**向后兼容**：缺少 `epistemic` 字段时默认为 `action_type: "answer"`。

参见：XSPEC-008、DEC-014 (PassiveQA)
